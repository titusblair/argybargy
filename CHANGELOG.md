# Changelog

## Unreleased
- **New CLI commands for running a stream: `argybargy room` / `post` / `close` / `reopen` / `rooms`.** Spinning one up was three commands, and the brief you handed the agent then had to carry a live bearer code typed out in the prompt, which is clumsy and puts a secret into every transcript that prompt touches. `argybargy room <name>` creates the room (so it lists in the dashboard before anyone has spoken), issues a worker code and an operator code, and prints a ready-to-paste block for the agent's brief: URL, code, the poll loop, the claim rule and the `should_exit` contract in three plain branches. That block is plain HTTP and plain English and is not specific to any model, so it works verbatim for a Codex session, another vendor, or a person with a terminal. `post`, `close`, `reopen` and `rooms` read the admin token from the state directory, so no operator command ever takes a token as an argument, and they default to talking to localhost rather than sending an admin token through a tunnel to reach a relay on the same machine (`--url` for a remote bridge). `rooms` also shows the per-room count of agents waiting on you. `invite`, `codes`, `revoke`, `token`, `serve` and `up` are unchanged.
- **Every roster row now says what the agent is doing.** `waiting` (it asked something nobody has answered), `working` (posted in the last two minutes) or `standing by` (live and polling, nothing outstanding: the finished-my-chunk-waiting-to-be-dismissed state that agents are now meant to sit in). All three are derived from `roster` and `waiting`, which `/admin/state` already returns, so nothing new is stored and nothing is inferred from message text. Offline and invited rows keep their timestamp and get no state, because naming one for an agent nobody has heard from would be inventing it. The state sits on the model line rather than in the right-hand rail, so it never squeezes the agent's name out of a 256px sidebar.
- **The dashboard now leads with an operator inbox: who is blocked on a human, and for how long.** Six agents posted a question on the same day, waited, got no answer because the operator was elsewhere, and each decided alone; one of those decisions stopped a change that would have moved 724 live phone numbers onto a single provider with no failover. Every question was already in the relay and nothing put them on one screen. `GET /admin/state` now carries `waiting`: every unanswered question across **all** rooms (not scoped by `?room=`, since the point is the room you are not looking at), longest wait first, each row carrying the asker, the room, the text, `expects_reply_resolved`, `claimed_by` and `waiting_seconds`. The sidebar draws it above the room list, clicking a row opens that room with the composer focused, a wait past five minutes turns red, and nothing waiting renders nothing at all rather than an empty box. **Answered means the party the question addressed spoke again in that room after it was asked**, not a claim, not any traffic, not the asker's own follow-up; a claimed question stays on the list because a claim is a promise and a claimer that went quiet is the case worth seeing. Closed rooms and the operator's own questions are skipped. Nothing new is stored: it is derived from the message log, with a partial index over the asking messages.
- **Closed rooms now hide from the dashboard sidebar by default.** Nine rooms were closed in a single day and the room list turned into an archive with the live work buried in it. Closed rooms now fold away behind one `Closed · N` row that says how many are hidden; clicking it reveals them and clicking again puts them back, and the choice persists in `localStorage` alongside the admin token and the theme rather than resetting on every refresh. The room you are currently reading is never folded away, even after it closes, so closing a room dismisses its agents without yanking the conversation out from under the operator. With nothing closed there is no control at all, rather than an empty one. No server change: the sidebar already had `room_status` for every room.
- **Rooms now have an operator-controlled lifecycle, and this changes how agents are meant to behave.** An agent used to finish its task and exit, which made the channel one-way in practice: you came back with a follow-up and found nobody there. An agent now stays in the room and keeps polling until the *operator* closes it. New admin endpoints `POST /admin/rooms/{room}/close` and `POST /admin/rooms/{room}/reopen` (existing admin dependency, both audited), and a **Close room** control in the dashboard header with the open/closed state on every sidebar row. Status is durable in SQLite, so it survives a restart; a room nobody has closed is open, and rooms are still created by their first message.
- **`GET /messages` now tells a poller whether to keep waiting.** Same response plus `room`, `room_closed`, `should_exit`, `exit_reason` and `poll_budget`. `messages` and `cursor` are unchanged, so a caller that ignores the new fields is unaffected. A long-poll already parked on a room **wakes the moment that room closes** instead of sitting out the rest of its 25 seconds, which is the difference between a clean exit and a stall. `GET /peers` is untouched.
- **A safety valve, so a forgotten room cannot burn an agent's wall clock forever.** `poll_budget` carries two clocks and takes the larger: `room_quiet_seconds` (since anyone posted here, durable and shared, reset by *any* message) and `waited_seconds` (since this agent received anything, which covers a room with no messages at all). At `ARGYBARGY_MAX_IDLE_SECONDS` (default 1800) the poll answers `should_exit` with `exit_reason: "idle_timeout"`, and an agent leaving that way should say it left because no close arrived, not because the work failed. `0` disables the idle bound; closing still dismisses everyone. It lives in the server response rather than in each agent's brief so that one env var retunes every agent at once and no agent has to invent its own bound.
- **Posting into a closed room now answers 409 `room_closed`** with who closed it and when. Nobody is reading a closed room, so a late post is a mistake worth surfacing rather than accepting into the void or dropping silently. The operator's own `POST /admin/say` still works, so a parting note in a room you closed is not blocked by your own switch.
- **`expects_reply: "anyone"` now resolves to a name when only one other participant could answer.** Messages carry a new `expects_reply_resolved`; in a room of two, "who can take this?" names who owes the reply instead of showing a generic badge. Computed at read time from durable membership (code holders plus everyone who has posted), so an agent that finished and went quiet still counts and the stored `expects_reply` is never rewritten. Anything reading `expects_reply` today is unaffected.
- **The dashboard now shows the model each agent is running.** `capabilities` was only rendered in the admin drawer's key list, which is not where you look to answer "what are we spinning up". It now sits under the agent's name on the sidebar roster row, ellipsised so a long string cannot stretch the row.
- **Unread marks now survive a page refresh.** The dashboard tracked the last message you had seen per room in memory only, so every reload started from nothing and lit an unread dot on every room you were not currently standing in. That mark is now kept in `localStorage` alongside the admin token and the theme. A stored mark above the room's own `last_seq` means the sequence restarted under you (a fresh database), so it resets rather than pinning the room permanently read.
- **The dashboard's agent list no longer empties when the relay restarts.** Presence is in-memory, so a restart wiped it and a peer aged out of it anyway, leaving rooms full of an agent's messages next to a blank agent list. `GET /admin/state` now also returns `roster`: per room, the union of the codes issued for it and everyone who has ever posted in it, with live presence attached as a status rather than used as a filter. The sidebar draws that roster for the room in view, so an agent that finished its work still shows, with when it was last heard from. `GET /peers` is unchanged and still answers "who is live in my room".
- **Per-room dashboard views.** The rooms sidebar now carries each room's message count, the age of its newest message, and an unread dot. The header shows the room's totals, and `/dashboard?room=<name>` is a deep link straight into one stream.
- **Fixed a quiet room rendering empty next to a busy one.** `GET /admin/state` only ever returned the last 60 messages across *all* rooms, so once one room got chatty it evicted every other room's history from the payload and those rooms drew as empty. `/admin/state` now takes an optional `?room=`, which returns that room's own tail. Unscoped calls are unchanged.
- **An unauthenticated dashboard now says so.** With no admin token in `localStorage`, `/admin/state` answers 401 and the page used to render a blank room with an empty rooms list, which read as a working relay with nothing in it. It now names the 401 and puts the token field one click away. No auth logic changed.
- **Now fully open source under the [MIT License](LICENSE)** © 2026 Titus Blair.
- **Fixed the dashboard's "expects" composer pill misreporting the default** — with no explicit choice it showed `—`, but `admin_say`/`POST /messages` were already defaulting `expects_reply` to the targeted peer (or `none` for a broadcast). The pill now shows that real default instead of hiding it.

## 1.0.0 — Hardening + Docker
**Stability**
- Codes now stored in **SQLite** (atomic issue/revoke) — fixes a data-loss race in the old JSON store.
- **Message retention** per room to bound disk growth (`ARGYBARGY_MAX_MESSAGES_PER_ROOM`, default 2000).
- New **`POST /messages/{seq}/claim`** — atomic first-responder claim (200 win / 409 lost) for open questions.

**Enterprise**
- Optional **hash-at-rest** for codes (`ARGYBARGY_HASH_CODES=1`).
- **Audit log** + `GET /admin/audit`; `GET /admin/stats`.
- 429 responses now include `Retry-After` and a machine-readable error body; optional **CORS**; **quotas**.
- Central env-var **config** (`argybargy/settings.py`) and **structured logging**.
- **CI**: ruff + pytest (3.10–3.13) + Docker build/smoke.

**Deploy & UX**
- **Dockerfile** + **docker-compose** (bridge + optional Cloudflare tunnel sidecar).
- New **`argybargy up`** — cross-platform one-command launcher (bridge + tunnel), works on Windows.
- **Capabilities** per agent, surfaced in `/whoami`, `/peers`, and the dashboard.
- Dashboard: send messages as a human, rooms + capabilities, claim/`expects_reply` badges, regenerate admin token.
